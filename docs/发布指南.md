# 把 ST Reader 发布到 GitHub（Windows 小白版）

目标仓库：**liangsheng-sys/st-reader**，首次版本：**0.1.0**。你使用浏览器和已经安装的 Git 即可，不需要 GitHub Desktop、gh、npm 或新的依赖。

本指南由你操作发布。准备材料不会自动创建仓库、推送代码、打标签或发帖；“发布材料写好了”也不代表 GitHub 上已经有仓库。

## 0. 发布前先拿到正确的 main

本项目每张任务卡使用一个分支，**main 不一定是最新代码**。T46 开工时 main 仍在 T40，而完整功能位于包含 I032 的后续分支。不要直接把旧 main 推上去。

先完成人类验收与任务板上的 **T47 发布前复查**，再让工程师把已验收的功能、这份发布材料和复查结果整合到 main，并告诉你“main 已准备好发布”。工程师负责处理分支和合并；下面的命令从这个状态开始。发布指南本身不替代 T47。

需要公开的内容是 Git 已提交的代码和文档。**不要把整个 E:\st-reader 文件夹打包上传**：`.dev/`、`.tmp/` 和 `docs/*.png` 不应发布，尤其 docs 下的两张截图含真实聊天文字。它们有忽略规则，但发布前仍应检查；不要用 `git add -f` 强行加入。

## 1. 用 GitHub 网页建一个空仓库

1. 浏览器登录 [GitHub](https://github.com)，确认右上角账号是 **liangsheng-sys**。
2. 打开 [新建仓库页面](https://github.com/new)。
3. **Owner** 选 `liangsheng-sys`，**Repository name** 填 `st-reader`。
4. 可把 Description 填成：`只读的 SillyTavern 聊天阅读器，支持批注、收藏与脱敏截图。`
5. 可见性选 **Public（公开）**。
6. **不要勾选 Add a README file**；**Add .gitignore** 和 **Choose a license** 都保持不添加。这些文件本地已经有了，新仓库应为空。
7. 点 **Create repository**。出现带 `Quick setup` 的空仓库页面即可，先留着这个标签页。

若 `liangsheng-sys/st-reader` 已经存在，打开它核对；不要再建一个同用途的新仓库。若里面已经有提交，让工程师先核对远端历史再继续。[GitHub 建仓说明](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)

## 2. 在 E:\st-reader 打开终端

1. 打开 Windows 文件资源管理器，进入 **E:\st-reader**。
2. 点窗口上方地址栏，输入 **powershell**，回车。应看到以 `PS E:\st-reader>` 开头的提示行。
3. 下面代码框里的命令**每次复制一行，粘贴后回车**；不要复制 `PS E:\st-reader>`。一行成功后再执行下一行，遇到红字或 `fatal/error` 先停下，把错误交给工程师。

先检查当前位置和工作区，再切到已准备好的 main：

```powershell
Get-Location
git status --short
git switch main
git branch --show-current
git log -1 --oneline
```

应看到位置 `E:\st-reader`；`git status --short` 没有输出；分支是 `main`；最后一行的提交编号与工程师给你的“发布提交”一致。若有未提交文件，先让工程师处理；不要自行丢弃文件，也不要照网上教程使用强制重置。

再核对公开文件：

```powershell
git ls-files manifest.json README.md CHANGELOG.md LICENSE
git ls-files .dev .tmp 'docs/*.png'
git log --all --format= --name-only -- .dev .tmp 'docs/*.png'
```

第一行应列出这四个公开文件；后两行应没有输出。第二行检查当前跟踪，第三行补查历史，避免把以前提交过的截图也推上去。如有输出先停下交给工程师核对，单纯新增忽略规则不会删除历史。

## 3. 告诉 Git 要推到哪里

首次设置仓库地址：

```powershell
git remote add origin https://github.com/liangsheng-sys/st-reader.git
git remote -v
```

`origin` 只是给这个 GitHub 地址起的本地名字。第二行应显示两条 `origin`，fetch 和 push 都指向上面的地址。

如果第一行说 `remote origin already exists`，先只执行 `git remote -v`。地址正确就跳过添加；地址不对时，把结果交给工程师改，不继续往别人的仓库推。

## 4. 第一次推送与浏览器登录

```powershell
git push -u origin main
```

首次需要认证时，会出现 Git Credential Manager 登录窗口或浏览器登录页。选择 **Sign in with your browser**（如果出现），在 GitHub 页面登录 **liangsheng-sys** 并按提示授权；启用了双重验证就照页面完成。回到终端等待上传结束。以前登录过并记住凭据时，可能直接成功，不再弹窗。

**这台电脑已随 Git 安装 Git Credential Manager（已核对 2.6.1，凭据助手为 manager）**，无需再装登录工具，也无需把 GitHub 密码填进命令。本流程不会下载到 C 盘的大型软件或依赖；工程文件和 Git 操作在 E 盘，浏览器和 Windows 凭据管理器会照常保存少量登录记录。[GitHub 登录与凭据说明](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git)

成功后通常能看到 `main -> main`、分支开始跟踪 `origin/main`；刷新 GitHub 仓库网页，文件列表应有 **manifest.json、index.js、style.css、src、vendor、README.md、CHANGELOG.md、LICENSE**，且首页下方显示中文介绍。

网页不应出现 `.dev`、`.tmp` 或两张真实聊天截图。不要把真实聊天、API Key、浏览器登录资料当作演示附件上传。[GitHub 本地仓库推送说明](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)

## 5. 给这次版本打标签

标签相当于给当前已验收的提交贴上固定版本号。保持在 main，确认上一步推送成功：

```powershell
git status --short
git branch --show-current
git tag --list
```

工作区应干净、分支应为 `main`。首次发布通常还没有标签；如果已经有 `v0.1.0`，先让工程师核对，不要删除或覆盖它。如果还有不打算公开的标签，也先核对再执行下方的 `--tags`。

```powershell
git tag v0.1.0
git push --tags
```

两行分开运行，是为了兼容 Windows 自带的旧版 PowerShell；作用就是“打标签成功后，再上传标签”。成功会出现 `v0.1.0 -> v0.1.0`。GitHub 仓库的 Tags 页面应能看到 **v0.1.0**。

## 6. 在网页发 Release

1. 在仓库首页点右侧 **Releases**，再点 **Draft a new release / Create a new release**；也可打开 [新建 Release 页面](https://github.com/liangsheng-sys/st-reader/releases/new)。
2. 在标签下拉框选已有的 **v0.1.0**。不要另建一个拼写不同的标签。
3. **Release title** 填：`ST Reader 0.1.0`。
4. 说明区填入下面的文字，或把 [CHANGELOG 的 0.1.0 部分](../CHANGELOG.md)复制进去。

   ```text
   ST Reader 0.1.0：只读的 SillyTavern 聊天阅读器。

   支持单聊/群聊、候选回复与思维链、划线批注和收藏、脱敏分享卡片，以及 HTML 当前画面截图、长图与自由框选。
   安装：ST 扩展 → 安装扩展 → https://github.com/liangsheng-sys/st-reader

   不修改聊天文件，不收集任何信息。完整源码公开，许可 AGPL-3.0。
   外链披露：没有扩展自有的第三方服务或遥测。用户 HTML 默认可以请求它引用的外部资源，截图默认带上图片、字体和样式；可在 Aa 或截图窗口关闭。安装更新由 ST/Git 访问 GitHub。详见 README。
   已知边界：外链素材受网站跨域许可限制；超长聊天打开时间仍有波动。分享前检查脱敏预览。
   ```

5. 无需上传整个工作目录或另做安装包，ST 直接从仓库安装。GitHub 会为标签提供源码下载。
6. 内容已核对就点 **Publish release**；想稍后发布则点 **Save draft**，草稿不会成为已发布版本。
7. 发布后应能打开 `https://github.com/liangsheng-sys/st-reader/releases/tag/v0.1.0`，看到标题和版本说明。[GitHub Release 操作说明](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)

## 7. 用仓库 URL 验证安装

这一步由你在 ST 界面操作。**已经通过目录联接使用开发版时，先处理旧联接，不能再装第二份**：关闭 ST，双击 **E:\st-reader\install\unlink-from-my-st.cmd**，按它的提示确认只移除了旧联接，然后重新启动 ST。它保留 E 盘源码；如提示拒绝删除或路径不符，停下反馈。完整联接说明见 [Windows 手册](SETUP_WINDOWS.md)。AI 不运行安装或卸载脚本。

1. 打开 ST 顶部 **扩展 → 安装扩展 / Install extension**。
2. 输入 `https://github.com/liangsheng-sys/st-reader`，分支留空，按提示安装。
3. 刷新页面，在 **管理扩展 / Manage extensions** 中看到 **阅读器 (ST Reader)**；确认版本为 **0.1.0**。
4. 点顶栏书本图标或魔杖菜单 **阅读器**，确认能选择聊天并阅读。不要为演示向公共仓库上传自己的聊天截图。
5. 如需演示图片，使用独立开发实例的虚构角色；先检查脱敏，再自行决定是否发布。当前 docs 下的两张真实截图不能使用。

发布者原先的目录联接与普通用户的 URL 安装是两条安装路径；普通用户只需上面 1–4 步。[ST 官方扩展安装说明](https://docs.sillytavern.app/extensions/)

## 9. 以后更新怎么做

**你是作者，要把修改发出去：**让工程师先完成修改、版本号、CHANGELOG、测试和提交；你验收后，让工程师整合到 main，并给出这次提交编号。不要自己用 `git add .` 把不认识的文件全加进去。

回到 E:\st-reader 的 PowerShell，一行行执行：

```powershell
git status --short
git switch main
git log -1 --oneline
git remote -v
git push origin main
```

仍须确认工作区干净、提交编号正确、远端是自己的仓库。上传成功后，普通用户就能通过 ST 的扩展更新取得代码；**发 Release 本身不代替 push main**。

如果工程师把新版本定为 **0.1.1**，并已同步 `manifest.json` 和 CHANGELOG，再执行以下示例；不要原封不动反复创建同一个版本号：

```powershell
git tag v0.1.1
git push --tags
```

然后重复第 6 节，在网页选择 **v0.1.1** 发新 Release，不改旧标签。

**你或普通用户，要在 ST 里取得更新：**打开 **扩展 → 管理扩展**，等待检查完成，找到 **阅读器 (ST Reader)**，有更新时点该行下载箭头（悬停提示 **Update available**）。完成后刷新页面；若页面仍旧，可按 Ctrl+F5。没有箭头可稍后重新打开管理面板检查。扩展声明了 `auto_update:true`，但具体自动检查/更新时机由 ST 决定，也可以手动更新。

仍通过 E 盘联接使用开发版时，显示的是该工作目录的文件；不要把 ST 的更新按钮当作合并任务分支的方法。让工程师管理这个本地仓库即可。

## 10. 遇到错误先看这里

| 看到什么 | 怎么处理 |
|---|---|
| `not a git repository` | 关闭该终端，从资源管理器的 E:\st-reader 地址栏重新打开 PowerShell |
| `remote origin already exists` | 用 `git remote -v` 核对；正确就跳过添加，不重复建仓 |
| `Repository not found` / 403 | 核对仓库已创建、地址正确、浏览器登录的是 liangsheng-sys；不要改成陌生地址 |
| `non-fast-forward` / `rejected` | 本地与远端历史不一致，把完整错误交给工程师；不要使用强制推送 |
| `tag 'v0.1.0' already exists` | 标签可能已建好，先让工程师核对，不删除或覆盖 |
| ST 提示扩展已存在 | 检查是否仍是旧目录联接，按第 7 节处理；不要手工删除整个 ST 数据目录 |
| 找不到阅读器入口 | 刷新页面，确认管理扩展中已启用；把 ST 版本和具体报错反馈给工程师 |

不需要为这些步骤安装 GitHub Desktop 或 gh，也不要把 GitHub 密码、登录验证码、令牌发给别人。
