## 先回答你问的三件事

1. **需求是不是太多？要拆吗？** 要，拆成两个版本。0.3.0 只修"信任"问题：备份、缓存不新、整楼显示失败、卡片丢美化。0.3.1 做阅读打磨：跟随条和上下楼、脱敏统一、滚动流畅、SVG。两样进 v2：HTML 里划线、离线 HTML 导出。
2. **astra 不在，Opus 顶上。** 已拍板 D32：Opus 临时可以改 core，但合同只能加不能改、只读名单不能放宽、三套自测必须全绿、交接信要单列"core 改动"。CLAUDE.md 末尾加了这段临时授权。
3. **TT 要不要单独版本？** 不要（D37）。TauriTavern 是用 Rust 重写了 ST 后端的桌面/手机壳，页面里拦截 `/api` 请求转给本地处理，声明扩展 API 对齐 ST 1.18.0，第三方 UI 扩展能装能更新。一套代码即可；要修的是手机竖屏顶栏关闭键被挤出屏幕（T80）。AI 不会去下载安装 TT。

## 关于"小剧场管理器"

看了它的脚本：所有数据直接写进 ST 的 `extensionSettings`，再调 ST 自带的 `saveSettingsDebounced`。ST 会把它存进服务器的 settings.json，自动轮替备份，换浏览器也在，所以你从没担心过。我们的批注量可能到几 MB，不适合塞进 settings.json 拖慢 ST，所以 D33 是：大数据自动写到 ST 服务器的 `user/files/` 目录（每天留一份、最多 7 份），小开关走 settings。效果一样：清站点数据、换浏览器都自动恢复。真正的第三方云（网盘、账号）不做，这是 NF3 的红线；你 ST 的 data 目录本身可以用自己的同步工具备份。它的脚本没有许可声明，我们不复用它的代码，不需要致谢。那份 `小剧场管理器.json` 留在 feedback 文件夹本地即可，不入库。
