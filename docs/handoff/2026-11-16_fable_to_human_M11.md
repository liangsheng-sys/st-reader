## 先说两个我读代码时查到根因的问题

**1. 絮语主题的字幕条——是我们的问题，不用去麻烦美化那边。** 你说"如果需要美化那边做兼容就忽略"，我读了絮语的主题文件：字幕条就是一条普通规则 `#chat .mes_text q { background: var(--xy-sub-bg); … }`，带 `#chat` 前缀，本该被我们原样克隆到阅读器里。但我们克隆样式的代码（`src/core/cssScope.js`，astra 9 月写的）有一条保守规则："背景这类可能引用图片的属性，只要值里用了变量就整条不要"，怕变量间接指向外链图片。于是条底没了，只剩反色的字，看上去就是"没有显示"。修法已拍板（D46）：变量能顺藤摸瓜查到是纯色、不含外链地址，就放行。这是 0.4.1 第一张卡（T100，astra）。

**2. 社区说"从一楼导出只有最近几层"——你猜对了，是隐藏楼。** 导出对话框里"系统楼和隐藏楼"是一个勾、默认不勾，而在 ST 里点过小眼睛隐藏的旧楼和系统提示楼在文件里是同一个标记。很多人隐藏旧楼省上下文，整本导出就只剩没隐藏的几楼。拍板 D47：拆成两项，"酒馆里隐藏过的楼"默认勾上，"系统提示与旁白"默认不勾，对话框实时显示"将导出 N 楼（跳过 M 楼）"。引擎部分 T101（astra），对话框部分并进 Opus 的 T99。社区用户现在的临时办法：导出时把"系统楼和隐藏楼"勾上。

## 番外怎么做（D48，你看一眼对不对）

阅读器顶栏多一个"正文 / 番外 / 全部"切换（这个聊天没有番外时不出现）。什么算番外，Aa 里三种规则随便开：

1. **标签**：模型在角色楼里顺手写的小剧场，你填开始 / 结束标记（默认 `<小剧场>` `</小剧场>`，也可以填 `<details><summary>番外` 这种，或一条正则）。只把那一段拎出去，同一楼其余正文留在正文页。
2. **关键词**：你发的"请暂停正文，写一个小剧场"这类用户楼，含关键词（默认"小剧场、番外、if线、平行世界、暂停正文"，可改）的用户楼和它后面直到你下一条消息之前的角色楼，整楼拎出去。
3. **隐藏楼**：你在 ST 里点小眼睛隐藏过的楼算番外。

正文页里被拎走的地方留一条淡色折叠条"番外 · 约 N 字 · 去番外看"，点了跳过去；番外页每条带"第 N 楼"，点了跳回正文。楼号不变，划线收藏在两边都在。导出为文档也能选"只正文 / 只番外"。不做"自动猜哪段是番外"。

## 卡片怎么改（D49）

五个项目里我能打开的三个 README 的要点在 `docs/research/参考项目对比.md` 末节。共同好看之处是：页眉（小图标 + 标题 + 日期）、一句按语、正文用编辑感字体与宽行距、页脚（作者 / 字数），配色是几十组精选渐变让人只选不调。我们这么学：加页眉、按语、页脚三组可关的小件；排版给字号 / 行距 / 字距 / 对齐 / 内边距 / 圆角几档；配色 16 组预设 + 自定义两色；纹理纯 CSS（格纹 / 点阵 / 横线）；字体只能挑本机已有的（不下载）。**不做**二维码、头像、真名。现有四套模板保留。调好后"另存为模板"，模板能导出成 JSON 文件分享、也能导入别人的；高手可在 JSON 里附一段 CSS，导入时会清洗（去外链、去字体下载、只许作用在卡片内）。
