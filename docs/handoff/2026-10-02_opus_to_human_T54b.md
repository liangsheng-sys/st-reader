# T54b 交接：阅读器里能看版本、检查更新、一键更新；更新后告诉你改了什么

分支：`task/T54b-update-ui`，从 astra 的 `task/T54a-update-core`（含 main、I041）开始。不含 T50/T52（在 `task/T52-width` 上），合并时互不冲突的代码文件只有 `reader.js`、`style.css` 两处需要一起合。

## 做了什么

- **Aa → ⋯ 最上面一行"版本"**：`ST Reader v0.1.0  [检查更新]  状态小字  更新日志  ○更新后提醒`。版本号读扩展自己的文件，不写死（升到 0.2.0 是 T57 的事）。
  - 点"检查更新"：ST 去 GitHub 看本扩展有没有新提交（只看本扩展，不碰聊天）。结果五种：
    - 开发目录 → "开发目录，不可更新"，没有更新按钮；
    - 已最新 → "已经是最新版本"；
    - 有新版 → "有新版本" + **立即更新**；
    - 更新完成 → "更新完成，刷新页面后生效" + **刷新页面**；
    - 出错 → 中文原因，按钮变"再试一次"。
  - 只在你点按钮时检查 / 更新，从不自动。
- **本次更新了什么**：更新后第一次打开阅读器，正文上弹一张纸，内容是更新日志里当前版本那一段。按 Esc、点 ✕、点外面或"知道了"都能关。弹过一次就不再弹。
  - 底部有"以后更新不再提醒"；勾上以后的更新都不弹。想再打开：Aa → ⋯ → "更新后提醒"。
  - 从没记录过（比如从 0.1.0 升上来——0.1.0 还没有这个功能）也会弹：升级的人正需要看到。
- **更新日志**链接：同一张纸，列出所有版本。
- 这张"纸"（文档面板）是通用的，T55 的使用说明也用它。

## 人类验收步骤

**A. Opus 验收实例（约 3 分钟）**

1. 双击 **E:/st-reader/.tmp/opus-dev/start.cmd**，看到 listening 后打开 **http://localhost:8101**，按 **Ctrl+F5**。
2. 打开任意聊天的阅读器（顶栏书本按钮）。**应马上弹出一张"ST Reader v0.1.0 更新了什么"**，里面是"阅读与整理 / 脱敏与分享 / 安装与许可 / 已知限制"几段。
3. 点 **知道了**。关掉阅读器再打开：**不再弹**。
4. 点右下 **Aa** → 右边 **⋯**：最上面一行是"版本 ST Reader v0.1.0 [检查更新] 更新日志 ●更新后提醒"。
5. 点 **检查更新**：显示"**开发目录，不可更新**"，没有"立即更新"按钮（这是验收实例，故意不让它更新）。
6. 点 **更新日志**：弹出同一种纸，标题"更新日志"，下面是 0.1.0 一节。按 **Esc**：只关掉这张纸，阅读器还开着。
7. 把"更新后提醒"关掉再打开，开关跟着变（这里没法演示"真的有更新"，见 B）。

**结束**：8101 黑窗口按 **Ctrl+C**，输入 **Y** 回车。

**B. 你自己的 ST（v0.2.0 发布之后）**

8. 按发布指南更新到 0.2.0 后打开阅读器：应弹"ST Reader v0.2.0 更新了什么"。
9. Aa → ⋯ → **检查更新**：应显示"已经是最新版本"。以后作者再发新版时，这里会出现"有新版本 / 立即更新"；点了之后显示"更新完成"，再点"刷新页面"。

## 已知问题 / 没做的

- "有新版本"时不显示新版本号：ST 只告诉"落后了"，不告诉对方是几号（合同如此）。
- 立即更新是 ST 在后台做 git pull，可能要几十秒；期间显示"正在更新…"。
- 更新后的弹窗内容取决于 CHANGELOG 写得好不好；0.2.0 那一段由 T57 写，建议写成给用户看的话。

## 给下一个人的话

- **8101 实例又改了一处**：`isolate.mjs` 照 astra 的开发实例做法，让宿主 public 里的同名扩展不再遮蔽，并给阅读器 manifest 打"开发目录"标记（检查更新零 Git）。因此扩展联接改回 `extensions/st-reader`（core 只认这个目录名），测试脚本路径也是 `third-party/st-reader/`。
