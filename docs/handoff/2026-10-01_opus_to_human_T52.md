# T52 交接：HTML 块和正文融为一体，宽了就伸出、再宽就缩小，正文宽度跟 ST 一样

## 做了什么（对应反馈 2 的三张截图）

1. **白框没了**：HTML 区块不再有外框和白底，网页自己是什么底色就是什么底色，和 ST 里酒馆助手的观感一致。
2. **不该被框住的文字放出来了**：一楼里"散文 + 网页 + 散文"时，只有网页部分进 HTML 区块；前面的"『…』"标题和后面的尾声都是正文，按主题排版，能划线。一楼里有两段网页，就有两个区块，中间的散文照常显示。（这是 astra 的 T51 在界面上的接线，06 的 I038。）
3. **"跟随 ST"的正文宽度 = ST 聊天栏的实际宽度**：直接量 ST 聊天栏此刻有多宽，窗口或 ST 设置一变就跟着变。实测和 ST 聊天栏宽度误差 0px。
4. **桌面 1200 不再被截掉**：比正文宽的网页先向两边伸到窗口边（左右各留 16px）；窗口还是放不下，就整块等比缩小，工具条右边会出现小字"已缩放 81%"。区块高度跟着缩小，下面不留空白。滚动模式和分页模式一样处理。
   - 截图 3 里左边被切掉的真正原因有两个：ST 自己给楼层设了"超出部分隐藏"，以及区块用居中排版时左侧被推出了可视范围。两处都改了。

- `src/ui/htmlBlocks.js`：散文和网页分开（按 core 给的每一段，在排好版的正文里对上相应的元素）；伸出 / 等比缩小 / 高度收紧 / "已缩放"小字；只在宽度变化时重算，避免阅读位置被推走

## 验收后补充（2026-10-02）

**人类反馈**："没有底色的普通正文也有底色了。"

**原因**：模型写的网页常带一段样式，比如"段落加浅色底"。在阅读器里，这段样式原本会作用到整页所有段落。以前 HTML 那一楼的散文整楼藏在区块里看不见；T52 把散文放回正文后，它们（以及别的楼、HTML 工具条本身）就被染上了卡片的底色。这和 T50 的"整页居中"是同一个根因。

**修法**：
- 把 T50 分支合进本分支：每楼自带的样式只管自己那个 HTML 区块，散文、别的楼、阅读器自己的工具条都不受影响；卡片本身的配色不变。
- 顺带修了一处：区块伸出正文时，这一楼的名字行和 ⋯ 按钮被撑到楼外。

**所以 T50 和 T52 现在要一起合并、一起验收。** 本分支已包含 T50 的全部内容。
- 06 里 T50 的问题号由 I040 改为 **I044**（astra 的 T53 分支已用 I040）。
