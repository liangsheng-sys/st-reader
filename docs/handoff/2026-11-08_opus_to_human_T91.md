# T91 交接：左边抽屉再打开时直接出内容，记得上次停在哪；多了一个 ↻ 刷新

## 做了什么

**1. 抽屉列表记在内存里（D41，反馈 3）**
- 以前每次打开阅读器、展开抽屉，都要先出几条灰色占位条，等 ST 把列表重新查一遍。
- 现在同一个网页里，第二次起：
  - 直接显示上次的列表，不出灰条；
  - 同时在后台问 ST 一遍，**有变化才**原地换上新的；
  - 换的时候，你眼睛正看着的那一行留在原处，列表不往上下跳。
- 抽屉还记得：
  - 上次停在哪一栏（最近 / 按角色 / 收藏 / 当前）；
  - "按角色"里展开了哪几个角色；
  - 每一栏滚到了哪里。
- 只记在内存里，不写进浏览器存储。刷新网页（F5）就清空，第一次打开照旧出灰条。

**2. ST 里有动静时，相关列表自己更新**
- 阅读器只读地听 ST 的这些事：发消息、收消息、改、删、换候选、换聊天、新建聊天、删聊天，以及新建、改、删角色或群组。
- 听到后，只把受影响的列表记成"要更新"：
  - 消息类 → "最近"，加上当前角色或群的聊天列表；
  - 删聊天 → "最近"，加上列着这个聊天的角色；
  - 改角色 → 角色表；改群组 → 群组表。
- 阅读器开着时，约 1.5 秒后统一重读（等 ST 先把聊天存完）。
- 阅读器没开时一个请求都不发，下次打开再说。
- 这些事件名我都对着 ST 源码 `public/scripts/events.js` 核对过。这个 ST 里没有的事件就跳过。

**3. 抽屉页签右边多了 ↻**
- 点一下：图标转圈，只把当前这一栏绕过缓存重新读一遍。
- 读的时候列表不清空，读回来原地换。
- 读不到会提示一句"没刷新上：……"。

**4. 文档**
- `README.md`：在隐私那段"同一次页面会话内……"补了一句：列表也只缓存在内存，刷新页面即空。
- `docs/使用说明.md`：补了抽屉会记住位置、可以点 ↻。

要测"在 ST 里发消息"，得用 **8101**。8100 有只读保护，ST 自己存聊天也会被拦下。

1. 双击 `E:\st-reader\.tmp\opus-dev\start.cmd`，等窗口里出现 listening。
   - 如果窗口里是 `EACCES ... 8101`：说明 8101 号端口这会儿被你的代理软件（Clash Verge）的一条连接占着。我刚才就遇到了。

3. 点顶栏的书本图标打开阅读器，再点左上角 **≡** 打开抽屉。第一次可能闪一下灰条，这是正常的。
4. 点 **👤 按角色**，点开一两个角色，往下滚一点。然后点右上角 **✕** 关掉阅读器。
5. 再点书本 → **≡**：
   - 应看到：直接是"按角色"；
   - 刚才展开的角色还展开着；
   - 滚动位置和刚才一样；
   - 没有灰条。
6. 关掉阅读器。在 ST 里点开一个**不在"最近"第一位**的角色（比如"星灯"），在输入框打 `/send 测试一下` 回车。
   - 用 `/send` 是因为它只把你这句话存进聊天，不会去叫 AI。
7. 再点书本 → **≡** → **🕘 最近**：应看到"星灯"那个聊天排在第一。
   - 可能先看到旧顺序，一眨眼换成新的。
   - 换的时候列表不跳。
8. 点页签右边的 **↻**：应看到图标转一下，列表不会变空。
9. 按 F5 刷新网页，再打开阅读器和抽屉：第一次会照旧闪一下灰条（缓存清空了）。
10. 验收完关掉那个黑窗口。

## 已知问题 / 没做的
- **8101 端口被代理占用**：今天 8101 号端口正好被 Clash Verge（`verge-mihomo.exe`）的一条对外连接占着，ST 起不来，报 `EACCES`。这不是阅读器的问题，连接断开后就好了。备用的 `.tmp/t91/start-8102.cmd` 留着。
- 列表缓存只在阅读器开着时随事件自动更新。阅读器关着时不发请求，所以重开时可能先看到旧顺序、一眨眼再换。这是有意的：不打开阅读器就不打扰 ST。
- "按角色"页的排序下拉和标签筛选，仍然只在这次打开期间有效（T43 的原规则）。D41 只要求记页签、展开的角色和滚动位置。
