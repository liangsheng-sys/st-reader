# 人类操作手册（Windows）

## 0. 先决条件
- 你的 SillyTavern 在 `F:\Claude\xinllm\SillyTavern`（1.14.0）。**F 盘只剩 145 MB**，先清出 ≥ 5 GB，否则 ST 自己都可能保存失败（T01）。
- 本仓库在 `E:\st-reader`。所有开发文件、临时文件都只在这里。
- 已装：Node 24、git、Codex CLI、Claude Code。

## 1. 给 AI 开工
1. 打开终端，进入 `E:\st-reader`。
2. astra：运行 `codex`；Opus：运行 `claude` 后用 `/model` 切到 Opus 5.5。
3. 把 `docs/prompts/` 里对应文件的全文粘贴为第一条消息。
4. AI 做完会告诉你怎么验收。你只回答"是 / 接近 / 不是 + 一句话"，记到 `docs/07_FEEDBACK.md`（可让 Claude Code 帮记）。

## 2. 启动开发实例（T10）

### 第一次打开
1. 打开资源管理器，在上面的地址栏粘贴 `E:\st-reader\dev`，按回车。
2. 双击 **start-dev-st.cmd**。不需要管理员权限，也不需要安装依赖。
3. 保持弹出的黑窗口打开。第一次 ST 会初始化默认资源并编译自己的前端，可能需要几分钟。看到 **SillyTavern is listening on IPv4: 127.0.0.1:8100** 就准备好了。
4. 打开浏览器，在地址栏输入 **http://localhost:8100**。如果出现欢迎页，在用户名框填一个虚构名字（例如“测试读者”），点“保存”。不需要连接 AI 服务。
5. 点页面顶部的 **积木图标（扩展）**，再点 **管理扩展**。在 **Installed Extensions** 中应看到 **阅读器 (ST Reader) 0.0.1**，左侧复选框已勾选。
6. T10 只交付开发环境和保护措施，现在还没有阅读器按钮、合成聊天或完整界面。ST 自带的示例角色、背景和预设属于程序默认资源；我们的测试角色与聊天由 T11 生成。

### 检查只读保护
1. 在开发实例页面按 **F12**（笔记本可能需要 **Fn+F12**），选择 **Console / 控制台**。
2. 应看到两行日志：`[st-reader] 开发实例只读保护已开启。` 和 `[st-reader] T12 数据与格式化模块已就绪，阅读器界面待 T21 接入。`。如果看不到，刷新一次页面。
3. 输入 `await window.stcrSelfTest({core:false})`，按回车。应看到 13 项 `passed: true`，最后显示“全部通过（13 项）”。这个模式只用内存替身，不会向服务器发送测试请求。
4. 也可以直接打开 **http://localhost:8100/?stcrSelfTest=1&core=0**，它会在页面初始化完成后运行同一套保护测试；仍在控制台看结果。T12 完整检查见 §2.2。

保护只在本机 **8100** 端口默认开启；`localhost`、`127.0.0.1`、`[::1]` 地址均可识别（当前服务配置只监听 IPv4）。它会拦截整个开发页面通过 `fetch` 发出的禁用聊天写入请求，包括 ST 自己的保存或删除动作，报错名为 `StcrReadonlyError`。不要在开发实例中发送、编辑或删除聊天；后续使用生成器准备合成数据。这个保护不是所有网络通道的安全沙箱，扩展仍须遵守 D02，逐次做只读审计。

### 重复启动与停止
- 以后仍双击同一个 cmd。已有正确配置和目录联接会复用，不覆盖开发聊天与设置。
- 停止时切到黑窗口，按 **Ctrl+C**；如果询问“终止批处理操作吗”，输入 **Y** 再回车。正常退出会清理本次 `.tmp` 临时目录。直接关闭黑窗口也会停止服务，但可能留下临时目录。
- 若提示 **8100 端口不可用**，先关闭上次启动的开发实例窗口，再双击；脚本不会替你关闭其他程序。
- 若提示配置中的 `dataRoot`、`port`、`listen` 或 `whitelistMode` 不符合要求：停止开发实例，用记事本打开 `E:\st-reader\.dev\config.yaml`，对照 `E:\st-reader\dev\config.dev.yaml` 恢复这四项，保存后重试。不要改成真实 ST 的数据目录。
- 若提示已有扩展目录不是正确联接，脚本会停止并保留原目录。把完整提示发给工程师，不要删除里面的文件。

### 文件在哪里（给接手工程师）
- `.dev/config.yaml` 首次从受版本管理的 `dev/config.dev.yaml` 创建，四项固定值是 `dataRoot: E:\st-reader\.dev\data`、`port: 8100`、`listen: false`、`whitelistMode: true`。ST 会自动补全自己的其他默认配置，后续启动不覆盖它。
- `.dev/data/default-user/extensions/st-reader` 是指向 `E:\st-reader\extension` 的 **目录联接**。没有复制扩展，也没有在真实 ST 数据目录中建立联接。
- 启动器仍运行现有 `F:\Claude\xinllm\SillyTavern\server.js`，始终显式传入固定的 `--dataRoot` 与 `--configPath`，不接受用户传入替代路径。Node 临时目录位于 `.tmp/stcr-runtime-*`，编译缓存位于 `.dev/data`。
- `dev/isolate-dev-st.mjs` 通过 Node 的 `--import` 仅调整开发进程内的全局扩展目录到 `.dev/global-extensions`、程序备份目录到 `.dev/program-backups`。因此“管理扩展”不会枚举或更新 F 盘的全局第三方扩展；F 盘源码没有修改。内置正则等系统扩展照常加载。
- 开发设置首次从 ST 程序自带的默认设置创建，初始 AI 后端选本地、未连接；关闭模型和分词器下载、第三方扩展自动更新、服务端插件。不会读取或复制真实用户设置。
- `.dev/` 与 `.tmp/` 均被 Git 忽略。Node 24 自测命令：在仓库终端运行 `node dev/selftest.mjs`；仅初始化不启动：`dev\start-dev-st.cmd --prepare-only`。

## 2.1 生成并验收合成数据（T11）

### 准备样本
1. 如果开发实例的黑窗口仍在运行，按 **Ctrl+C** 停止；询问终止批处理时输入 **Y**。生成器需要离线改开发设置，端口被占用时会停止并提示。
2. 在资源管理器打开 `E:\st-reader\dev`，双击 **generate-fixtures.cmd**。应显示“已生成 3 位虚构角色、1 个群聊、4 份单聊”和“大文件：21.35 MiB”，最后“全部通过（36 项）”（T12 已追加 core 检查）。按任意键关闭。
3. 双击 **install-test-font.cmd**。首次从官方仓库下载锁定版本的 Ny-font-manager 与测试字体，总计约 700 KiB，单个文件均小于 5 MB；再次执行只校验已有文件，显示“本次下载 0 字节”。看到“安装/校验完成”后按任意键关闭。若网络失败，稍后重试；若提示校验不符，把提示发给工程师。
4. 双击 **start-dev-st.cmd**，等黑窗口显示 listening，然后打开 **http://localhost:8100**。本次交付已经完成样本生成和扩展安装，直接从这一步开始也可以。

重复生成会恢复 STCR 测试聊天、正则和测试主题；不会删除其他开发数据。文件清单在 `.dev/fixtures/manifest.json`；头像与故事均为虚构，不用连接任何 AI 服务。

### 看角色、群聊和主题
1. 点顶栏最右边的 **角色管理（名片图标）**。应看到 **星灯（虚构）**、**纸舟（虚构）**、**雾岚（虚构）** 和 **STCR · 雾岛观测队（虚构）**。ST 自带的 Seraphina 是程序默认示例。
2. 点 **星灯（虚构）**。聊天最后一楼应显示 **候选 3/5**；正文中可见 **【一次】✓**、**星灯作用域命中** 和 **近景命中**。往上滚，较早楼层保留 **【近景】**，证明深度限制有效。“思考了一会”可点击展开，里面是明确标记为虚构的测试思维链。不要点候选左右箭头、编辑或发送，T11 只检查样本；阅读器的只读候选切换由后续卡交付。
3. 再点角色管理面板左上角的 **选择/创建角色（列表图标）** 回到列表，点 **纸舟（虚构）**。向上滚可看到三种语言的代码框、HTML 引号与表格、很长的一楼。正文左边有薄荷色边线，引号是金色，说明测试主题生效。
4. 回到列表，点 **STCR · 雾岛观测队（虚构）**。应看到测试旅人和三位成员共 4 楼。
5. 大文件在 `E:\st-reader\.dev\data\default-user\chats\STCR_T11_Mist\STCR-90-大文件-1600楼.jsonl`；资源管理器右键“属性”可见大小超过 20 MB。自动检查已验证 1600 楼逐行可解析；阅读器大文件性能在 T12/T30 验收。

### 本地字体兼容检查（每个浏览器做一次）
1. 保持网址为 **localhost:8100**。点顶栏 **积木图标（扩展）**，展开 **Ny字体管理器**，选 **导入字体**。
2. 在“本地字体文件”一栏点 **浏览…**，粘贴 `E:\st-reader\.dev\fixtures\fonts\JetBrainsMono.ttf`，点“打开”，再点面板里的 **导入字体**。
3. “已导入字体”下应出现 **JetBrainsMono**。点它的 **设为正文**；等几秒，让宿主保存设置，再刷新页面。
4. 打开 **星灯（虚构）**，正文的 `STCR FONT PROBE: iii WWW 0123456789` 应为等宽字体。测试字体覆盖拉丁字母和数字，中文用后备字体。
5. 按 **F12 → Console / 控制台**，粘贴 `await window.stcrSelfTest({fixtures:true, font:true, rendered:true})` 并回车。应看到 **全部通过（21 项）**：含原有 13 项保护测试、5 项样本检查、1 项原生显示检查、2 项字体检查。它只读聊天 API 与字体数据库。
6. 不想粘贴命令时，可打开 **http://localhost:8100/?stcrSelfTest=1&fixtures=1&font=1&rendered=1**，然后点角色管理并打开星灯；同样在控制台看结果。仅验收数据、不验字体时用 `await window.stcrSelfTest({fixtures:true})`，应通过 18 项。

若换浏览器或把网址改成 127.0.0.1，需重新导入字体，因为 IndexedDB 按浏览器与网址隔离。此处验证字体存储和正文应用；PNG 中的字体由 T14 验证。

## 2.2 验收数据与格式化引擎（T12）

本卡交付引擎，还没有阅读器窗口；T21 再接界面。下面两组检查都要通过。

1. 资源管理器打开 `E:\st-reader\dev`，双击 **test-core.cmd**。不需要先启动 ST。应逐行显示“通过”，最后 **全部通过（36 项）**；按任意键关闭。若提示尚无样本，先按 §2.1 生成。
2. 双击 **start-dev-st.cmd**，等 listening 后打开 **http://localhost:8100**。如果已在运行，直接用现有开发窗口。
3. 点顶栏最右边的**角色管理（名片图标）**，打开 **雾岚（虚构）**。若目前在某个角色详情页，先点面板左上角的**选择/创建角色（列表图标）**返回列表。页面应显示雾岚的普通三楼聊天；这样星灯处于“未选中”状态。
4. 按 **F12 → Console / 控制台**，粘贴 `await window.stcrSelfTest()`，按回车。等待最后出现 **全部通过（45 项）**，表格里的 passed 全为 true。检查会只读加载那份 21.35 MiB 合成文件，控制台另显示耗时。
5. 表格中应有策略 a 和 b 各自的“未选中星灯”“深度”“只跑一次”“思维链”通过项；页面仍停在雾岚，原生聊天没有切到星灯。这证明读取其他角色无需改 ST 当前选择或候选。
6. 不想粘贴代码时：按 F12 打开控制台，再在地址栏打开 **http://localhost:8100/?stcrSelfTest=1&coreWhenChat=1**，照第 3 步点雾岚，会自动执行同一套 45 项检查。

若误在星灯聊天里运行，会提示先打开雾岚；换到雾岚后再运行命令即可。出现“自测失败”或任一 false 时，把报错文字交给工程师，不要编辑聊天修样本。此检查不需要连接 AI、不需要重新导入字体；字体 PNG 验收在 T14。

## 3. 安装到你自己的 ST（T30 交付后）
1. 关闭 ST。
2. 双击 `E:\st-reader\install\link-to-my-st.cmd`。它只在 `F:\...\data\default-user\extensions\` 下建一个"目录联接"指向 `E:\st-reader\extension`，不复制、不读、不写你的聊天。
3. 启动 ST，扩展面板里启用"阅读器 (ST Reader)"。
4. 卸载：删除那个联接目录即可（`rmdir F:\Claude\xinllm\SillyTavern\data\default-user\extensions\st-reader`，只删联接不删 E 盘文件）。
