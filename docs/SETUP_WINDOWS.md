# 人类操作手册（Windows）

## 0. 先决条件
- 你的 SillyTavern 在 `F:\Claude\xinllm\SillyTavern`（1.14.0）。**F 盘只剩 145 MB**，先清出 ≥ 5 GB，否则 ST 自己都可能保存失败（T01）。
- 本仓库在 `E:\st-reader`。所有开发文件、临时文件都只在这里。
- 已装：Node 24、git、Codex CLI、Claude Code。

## 1. 给 AI 开工
1. 打开终端，进入 `E:\st-reader`。
2. astra：运行 `codex`；Opus：运行 `claude` 后用 `/model` 切到 Opus 5.5。
3. 把 `docs/prompts/` 里对应文件的全文粘贴为第一条消息。
4. AI 做完会告诉你怎么验收。你只回答"是 / 接近 / 不是 + 一句话"，记到 `docs/07_FEEDBACK.md`（可让 Claude Code 帮记）。

## 2. 启动开发实例（T10）

### 第一次打开
1. 打开资源管理器，在上面的地址栏粘贴 `E:\st-reader\dev`，按回车。
2. 双击 **start-dev-st.cmd**。不需要管理员权限，也不需要安装依赖。
3. 保持弹出的黑窗口打开。第一次 ST 会初始化默认资源并编译自己的前端，可能需要几分钟。看到 **SillyTavern is listening on IPv4: 127.0.0.1:8100** 就准备好了。
4. 打开浏览器，在地址栏输入 **http://localhost:8100**。如果出现欢迎页，在用户名框填一个虚构名字（例如“测试读者”），点“保存”。不需要连接 AI 服务。
5. 点页面顶部的 **积木图标（扩展）**，再点 **管理扩展**。在 **Installed Extensions** 中应看到 **阅读器 (ST Reader) 0.0.1**，左侧复选框已勾选。
6. ST 自带的示例角色、背景和预设属于程序默认资源；我们的测试角色与聊天由 T11 生成。T21 已提供顶栏书本按钮，T13 接入主题样式；批注与备份按钮由 T22 接入。

### 检查只读保护
1. 在开发实例页面按 **F12**（笔记本可能需要 **Fn+F12**），选择 **Console / 控制台**。
2. 应看到 `[st-reader] 开发实例只读保护已开启。`、`[st-reader] T13 样式、存储与锚点模块已就绪。` 和阅读器入口已挂载的日志。如果看不到，刷新一次页面。
3. 输入 `await window.stcrSelfTest({core:false})`，按回车。应看到 13 项 `passed: true`，最后显示“全部通过（13 项）”。这个模式只用内存替身，不会向服务器发送测试请求。
4. 也可以直接打开 **http://localhost:8100/?stcrSelfTest=1&core=0**，它会在页面初始化完成后运行同一套保护测试；仍在控制台看结果。T12 完整检查见 §2.2。

保护只在本机 **8100** 端口默认开启；`localhost`、`127.0.0.1`、`[::1]` 地址均可识别（当前服务配置只监听 IPv4）。它会拦截整个开发页面通过 `fetch` 发出的禁用聊天写入请求，包括 ST 自己的保存或删除动作，报错名为 `StcrReadonlyError`。不要在开发实例中发送、编辑或删除聊天；后续使用生成器准备合成数据。这个保护不是所有网络通道的安全沙箱，扩展仍须遵守 D02，逐次做只读审计。

### 重复启动与停止
- 以后仍双击同一个 cmd。已有正确配置和目录联接会复用，不覆盖开发聊天与设置。
- 停止时切到黑窗口，按 **Ctrl+C**；如果询问“终止批处理操作吗”，输入 **Y** 再回车。正常退出会清理本次 `.tmp` 临时目录。直接关闭黑窗口也会停止服务，但可能留下临时目录。
- 若提示 **8100 端口不可用**，先关闭上次启动的开发实例窗口，再双击；脚本不会替你关闭其他程序。
- 若提示配置中的 `dataRoot`、`port`、`listen` 或 `whitelistMode` 不符合要求：停止开发实例，用记事本打开 `E:\st-reader\.dev\config.yaml`，对照 `E:\st-reader\dev\config.dev.yaml` 恢复这四项，保存后重试。不要改成真实 ST 的数据目录。
- 若提示已有扩展目录不是正确联接，脚本会停止并保留原目录。把完整提示发给工程师，不要删除里面的文件。

### 文件在哪里（给接手工程师）
- `.dev/config.yaml` 首次从受版本管理的 `dev/config.dev.yaml` 创建，四项固定值是 `dataRoot: E:\st-reader\.dev\data`、`port: 8100`、`listen: false`、`whitelistMode: true`。ST 会自动补全自己的其他默认配置，后续启动不覆盖它。
- `.dev/data/default-user/extensions/st-reader` 是指向 `E:\st-reader\extension` 的 **目录联接**。没有复制扩展，也没有在真实 ST 数据目录中建立联接。
- 启动器仍运行现有 `F:\Claude\xinllm\SillyTavern\server.js`，始终显式传入固定的 `--dataRoot` 与 `--configPath`，不接受用户传入替代路径。Node 临时目录位于 `.tmp/stcr-runtime-*`，编译缓存位于 `.dev/data`。
- `dev/isolate-dev-st.mjs` 通过 Node 的 `--import` 仅调整开发进程内的全局扩展目录到 `.dev/global-extensions`、程序备份目录到 `.dev/program-backups`。因此“管理扩展”不会枚举或更新 F 盘的全局第三方扩展；F 盘源码没有修改。内置正则等系统扩展照常加载。
- 开发设置首次从 ST 程序自带的默认设置创建，初始 AI 后端选本地、未连接；关闭模型和分词器下载、第三方扩展自动更新、服务端插件。不会读取或复制真实用户设置。
- `.dev/` 与 `.tmp/` 均被 Git 忽略。Node 24 自测命令：在仓库终端运行 `node dev/selftest.mjs`；仅初始化不启动：`dev\start-dev-st.cmd --prepare-only`。

### 本地字体兼容检查（每个浏览器做一次）
1. 保持网址为 **localhost:8100**。点顶栏 **积木图标（扩展）**，展开 **Ny字体管理器**，选 **导入字体**。

若换浏览器或把网址改成 127.0.0.1，需重新导入字体，因为 IndexedDB 按浏览器与网址隔离。此处验证字体存储和正文应用；PNG 中的字体由 T14 验证。

## 2.3 验收样式、存储和锚点（T13）

### 一次完整检查
1. 资源管理器打开 `E:\st-reader\dev`，双击 **test-core.cmd**。应显示 **全部通过（68 项）**。若报合成 PNG/聊天与清单不一致，停止开发黑窗口，按 §2.1 的“准备样本”第 2 步重建样本，再检查。不要修改清单来跳过错误。
2. 双击 **start-dev-st.cmd**，浏览器打开 **http://localhost:8100**。本次只使用这个地址，不换成 127.0.0.1。

6. 最后应显示 **全部通过（70 项）**。表格应包含主题更新、新增/删除 style、Ny 字体与 important、六类数据 JSON 往返、跨节点锚点、orphan 孤立与恢复、只读终检，全为 true。测试数据放专用表，结束时自动清理；已有批注与收藏不受影响。
7. 不想输入代码时，在地址栏打开 **http://localhost:8100/?stcrSelfTest=1&coreWhenChat=1&cardExport=0**，再照第 4 步点雾岚。保持控制台打开，自动跑同一套70项检查。若红字提示字体未加载，只按第3步处理后重跑；其他报错把文字发给工程师。

### 确认刷新后还在
1. 保持 F12 控制台打开，在地址栏打开 **http://localhost:8100/?stcrStorageProbe=write**。
2. 等控制台出现 **“刷新验证已写入”**。它只在自己的测试表放入虚构批注、收藏、屏蔽词、设置、规则和图片，并把批注标为孤立。
3. 把地址最后的 `write` 改为 `read`，回车，重新加载页面。
4. 应看到 **“跨页面持久化验证通过：六类数据与 orphan 均保留；专用测试表已清理。”**。如果没有，保留报错交给工程师。也可控制台先运行 `await stcrStorageProbe('write')`，F5 后运行 `await stcrStorageProbe('read')`。

### 肉眼看主题
1. 返回普通地址 **http://localhost:8100**，在宿主打开雾岚，点顶栏**书本图标**打开阅读器。在默认“原样”排版下，正文左侧应有测试主题的薄荷色边线，拉丁字母使用 Ny 正文字体。
2. 按 Esc 退出阅读器，点顶栏**用户设置（人形带齿轮图标）**，在“主题”下拉框选另一套已有主题。再打开阅读器，应随主题改变。
3. 退出阅读器，把主题选回 **STCR T11 · 雾岛纸页**；再次打开应恢复薄荷色边线。完成后按 Esc 退出，在黑窗口按 Ctrl+C 停止服务。

T13 交付的是底层与控制台检查。划线、收藏、导入/导出按钮由 T22 接入；T21 暂存的阅读设置/进度也由 T22 迁入本卡的 store.settings（I012），不把按钮未出现当成 T13 存储失败。PNG 导出及字体嵌入由 T14 验证。

## 3. 安装到你自己的 ST（T30）

安装/卸载脚本**只由你双击，AI 不运行**。它们使用已有的 Node.js，不下载或安装依赖。开始前在“此电脑”确认 F 盘至少空出 5 GB、E 盘至少 3 GB；浏览器下载位置改到 E 盘。

1. 关闭真实 ST 的网页和启动黑窗口。资源管理器地址栏粘贴 **E:\st-reader\install**，回车，双击 **link-to-my-st.cmd**。
2. 新脚本先显示 **`[ST Reader] link v2026-09-30`**，然后是“安装程序已启动”、两个固定路径。看到“**目录联接已建立**”和 **`Exit code: 0`** 才表示成功。唯一变更是建立 `F:\Claude\xinllm\SillyTavern\data\default-user\extensions\st-reader` → `E:\st-reader\extension`；不复制扩展，不读取或修改聊天，不创建其他目录。目标目录项已存在（含损坏联接）则提示并退出，绝不覆盖、删除。请保持 install 文件夹完整，不要把 cmd 单独移到桌面；它要读取同目录的两个 mjs 程序文件。
3. 如果显示“目标已存在”，不要盲删它；先保留提示。已安装同一个阅读器时可直接启动 ST 检查。若显示 **`FAILED`**，复制黑窗口中从版本行到 **`Exit code`** 的全部文字。若没有版本行，说明新脚本正文未开始执行，要同时说明你双击的文件位置；不要仅复制最后一句系统错误。若 node.exe 找不到，重新打开安装了 Node 24 的终端/资源管理器后重试；若显示 **`ENOENT`** 和父目录提示，由你在资源管理器确认约定 ST 位置及原有 `data\default-user\extensions` 目录是否存在。脚本不会创建父目录或自动寻找别的数据目录，AI 也不检查真实目录。
4. 按平常方式启动真实 ST，打开你平常的网址。顶栏积木图标 → 扩展，找到并启用 **阅读器 (ST Reader)**；刷新后顶栏出现书本图标。`localhost:8100` 是合成开发实例，不是本步的真实 ST。
5. 正式验收按 **[M3_验收清单.md](M3_验收清单.md)**。进入阅读器前先记下 ST 当前角色、聊天名、末楼正文和候选 `几/几`；退出后核对，**刷新后再核对**。清单开头另有由你自己导出前后 JSONL 并逐字节比较的方法。
6. 卸载时先退出 ST，双击 **unlink-from-my-st.cmd**。它先检查这一个目录项确为指向 `E:\st-reader\extension` 的联接，再只移除联接；不存在则提示无需卸载，普通目录或指向别处的联接则拒绝。没有递归删除，E 盘源码、聊天和浏览器里的批注都保留。重启 ST 后入口消失。

不要移动 `E:\st-reader\extension`，联接需要它留在原处。更新源码后刷新 ST 即可；不需要重复安装或 build。卸载不会备份批注/收藏，换浏览器前仍须按下一节导出 JSON。
